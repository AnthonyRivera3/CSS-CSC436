Practice

Ten labs. Write the CSS, prove it works.

Each lab gives you fixed HTML and a stylesheet with the interesting parts missing. The preview updates as you type. When you think you have it, hit Check my work — the page reads the computed styles of the result and tells you which requirements you met.

Before you start

  • Your work is saved in this browser as you type, per lab. Closing the tab is safe; Reset is not — it wipes that lab back to the starter.
  • Tab indents inside the editor. Press Escape then Tab to move to the next control instead.
  • The checks grade the result, not the technique. A lab can pass with a clumsy solution — the brief tells you which approach we are practising, and that is the one to use.
  • Stuck for more than ten minutes? Open Reveal one working answer. Read it, close it, then write it yourself from memory.
Lab 01Module 1 · Box model

Build the calling card

Make .card exactly 260px wide including its border, with 24px of padding, a 2px solid #e60012 border, and 12px rounded corners. The width must include the padding and border — that means setting box-sizing.

Lab 02Module 1 · Selectors

Highlight the current page

Every link in .nav should be #8a8f98. The link for the current page should be #e60012 and bold — and you must target it with the [aria-current="page"] attribute selector that is already in the HTML. No new classes, and no !important.

Lab 03Module 1 · Tokens

One token, two variants

Declare --chip-bg: #e60012 on :root. Use it with var() for the chip background — do not write the hex code inside .chip. Then make .chip--gold gold (#a67c22) by re-declaring the token on that class, not by setting background-color again.

Lab 04Module 1 · Typography

Fluid heading, readable paragraph

Size the h1 with clamp(2.5rem, 1.5rem + 3vw, 3.5rem), set it uppercase with text-wrap: balance. Give the paragraph a reading measure of 60ch and a line-height of 1.6. Drag the divider between the two panes to see the heading resize.

Lab 05Module 2 · Flexbox

The bridge toolbar

Lay .bar out as a flex row, vertically centred, with a 12px gap, allowed to wrap. Then push .cta — and only it — to the far end using an auto margin, not justify-content.

Lab 06Module 2 · Grid

A gallery with no media queries

Turn .gallery into a grid with a 16px gap whose columns are repeat(auto-fit, minmax(min(140px, 100%), 1fr)). You should end up with several columns, and no horizontal scrollbar at any width.

Lab 07Module 2 · Grid areas

The console shell

Build the app shell with named grid areas. Columns: 120px 1fr. The sidebar spans all three rows on the left; header, main and footer stack on the right. Assign each child with grid-area.

Lab 08Module 2 · Position

Pin the badge

Pin .badge to the top-right inside corner of .product, 8px from each edge. The badge must be positioned against the card — not the page — so the card needs to become a positioning context first.

Lab 09Module 3 · :has()

Style a parent by what's inside it

Give every .entry that contains a .tag a background of #f3e6c8 and a 4px solid #a67c22 left border — using :has(). Entries without a tag must stay exactly as they are. You may not add a class to the HTML.

Lab 10Module 3 · Motion

Motion that stays cheap

Transition only transform and opacity on .rune — in that order, over 0.3s — and lift it on hover with translateY(-6px). Then write a @keyframes pulse and run it on .glow. No transition: all, and nothing that animates width, top or margin.

Writing your own lab

A lab is one <div class="lab" data-lab="unique-id"> containing three templates, a JSON block of checks, and an empty mount point. assets/js/exercises.js builds the editor, the preview and the checklist from that. 

<div class="lab" data-lab="11-my-lab">
  <div class="lab__head">…title and brief…</div>

  <template data-lab-html>      <!-- the fixed markup -->
    <div class="thing">Hello</div>
  </template>

  <template data-lab-start>     /* what the student begins with */
    .thing { /* TODO: make it red */ }
  </template>

  <template data-lab-solution>  /* revealed on request */
    .thing { color: red; }
  </template>

  <script type="application/json" data-lab-checks>
    [{ "label": "It is red", "selector": ".thing", "prop": "color", "equals": "red" }]
  </script>

  <div data-lab-mount></div>
</div>

Every check option

KeyMeaning
labelWhat the student sees in the checklist. Required.
selectorAny CSS selector, including :has() and :not(). Defaults to body.
propThe property to read — including custom properties like --chip-bg.
pseudoOptional, e.g. "::before".
equalsA value, or an array of acceptable values. Compared against the computed value, so "#e60012" and "rgb(230 0 18)" both match.
notEqualsFails if the computed value matches. Good for "you must change this from the default".
containsSubstring match. Use for font-family, grid-template-areas.
min / maxNumeric range on the first number in the value. Use for sizes that can legitimately vary.
countExactly this many elements match the selector.
existsJust assert that something matches the selector.
Design checks around the outcome you can measure. A computed style cannot tell you whether a student used clamp() or a hardcoded pixel value that happens to land in range. State the technique in the brief, check what you can, and mark the rest by eye — the point is that the student can run the check themselves before they show you.
