01 — Normal flow, and choosing a tool

Before you reach for anything: block elements stack vertically and fill their parent's width; inline elements sit in a line. Most of the web is fine with that. Reach for a layout system only when normal flow genuinely can't do the job.

NeedReach for
Things in a row or column, sized by their contentdisplay: flex
Rows and columns that line up across the whole layoutdisplay: grid
A badge pinned to a corner, a sticky header, a modalposition
Text flowing around an imagefloat (yes, still, only for this)

02 — Flexbox: one axis

You set a direction, then you say how to distribute space along that axis (justify-content) and how to align across it (align-items). Getting those two straight is 80% of flexbox. 

.toolbar {
  display: flex;
  flex-direction: row;            /* main axis → horizontal */
  justify-content: space-between; /* along the main axis */
  align-items: center;            /* across it */
  gap: 1rem;                      /* never use margins for this */
  flex-wrap: wrap;                /* let it break instead of overflow */
}

The three properties on the children

.item {
  flex-grow: 1;     /* take a share of leftover space */
  flex-shrink: 1;   /* give space back when cramped */
  flex-basis: 0;    /* starting size before grow/shrink */

  /* Almost always written as the shorthand: */
  flex: 1;          /* = 1 1 0  → equal columns */
  flex: auto;       /* = 1 1 auto → sized by content, then grows */
  flex: none;       /* = 0 0 auto → never changes size */
}
The push-it-right trick: margin-inline-start: auto on one flex child shoves it and everything after it to the end. That's how the buttons in the lab toolbars sit on the right.

03 — Grid: two axes

Grid is the only layout tool that lets you align things across rows and columns at once. The magic function is minmax(), and the magic keyword is auto-fit. 

/* The responsive grid with no media query.
   "As many columns as fit, each at least 260px, sharing space equally." */
.grid {
  display: grid;
  gap: 1.5rem;
  grid-template-columns: repeat(auto-fit, minmax(min(260px, 100%), 1fr));
}

The min(260px, 100%) is not decoration: it stops the track from overflowing on a phone narrower than 260px.

Named areas — layout you can read

.console {

.console > nav    { grid-area: nav; }

04 — Positioning & stacking

ValueBehaviour
staticThe default. Ignores top/left entirely.
relativeNudged from where it was, but keeps its space. Mostly used to become a positioning context.
absoluteRemoved from flow. Positions against the nearest positioned ancestor.
fixedPositions against the viewport. Stays put when you scroll.
stickyNormal until it hits your top offset, then it sticks. Needs a scrollable ancestor.
 
.panel { position: relative; }        /* the anchor */

.panel .badge {
  position: absolute;
  inset-block-start: -8px;           /* logical: "top" in LTR */
  inset-inline-end: -8px;            /* logical: "right" in LTR */
  z-index: 2;
}

/* The header on this very page: */
.site-header { position: sticky; top: 0; z-index: 50; }
z-index only works on positioned elements (or flex/grid children). And a transform, filter, or opacity below 1 creates a new stacking context — your z-index: 9999 can only compete inside its own context. That is why "z-index doesn't work" is nearly always an ancestor's fault.

05 — Responsive design

Write the narrow layout first, then add at wider widths. Every breakpoint should exist because the design broke there — never because the number matches a phone you own. 

/* mobile first: this is the default */
.layout { display: grid; gap: 1rem; }

/* enhance upward */
@media (min-width: 48rem) {
  .layout { grid-template-columns: 220px 1fr; }
}

/* query capability and preference, not just size */
@media (prefers-reduced-motion: reduce)   { * { animation: none !important; } }
@media (prefers-color-scheme: dark)       { :root { --bg: #05070d; } }
@media (hover: hover)                     { .card:hover { transform: translateY(-3px); } }
Use rem in media queries, not px. A student who bumps their browser font size to 20px gets a layout that responds to that; a px breakpoint ignores them.

06 — Container queries

A media query asks how wide the window is. A container query asks how wide this component's parent is — which is the question you actually wanted to ask. The same card can be wide in the main column and narrow in a sidebar, with one stylesheet. 

/* 1. declare an element as a container */
.card-slot {
  container-type: inline-size;
  container-name: slot;
}

/* 2. query it — note "cq" units are relative to the container */
@container slot (min-width: 420px) {
  .card { display: grid; grid-template-columns: 90px 1fr; }
  .card h3 { font-size: 4cqi; }
}
Support: container queries and :has() are available in every current browser. If you must support something older, keep them as a progressive enhancement — the layout below the query should still be usable.
