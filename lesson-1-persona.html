01 — Selectors

A CSS rule is a selector, then a block of declarations. Each declaration is a property and a value. That's the whole language. 

.card {              /* selector */
  background-color: #151515;   /* declaration */
  padding: 1.5rem;
}

The selectors you will use ninety percent of the time:

SelectorMatchesUse it for
.cardclassAlmost everything. Your default.
#mainidAnchors and JS hooks — rarely styling.
buttonelementBase styles and resets.
[aria-current]attributeState that already exists in your HTML.
.card pany p inside .cardDescendants, at any depth.
.card > pdirect children onlyPrecision. Prevents leaking into nested components.
h2 + pthe p right after an h2Spacing between siblings.
.card:hoverstateInteraction.
.card::beforea generated childDecoration with no extra markup.
Rule of thumb: style with classes. Reach for element selectors only in your reset, and treat ids as off-limits for styling — you will regret their specificity within a week.

02 — Cascade & specificity

When two rules set the same property on the same element, the browser picks a winner in this order. Stop at the first tiebreak that decides it:

  1. Origin & importance — your author styles beat the browser's defaults; !important jumps the queue.
  2. Specificity — counted as (ids, classes, elements).
  3. Source order — last one written wins.
/* specificity 0,1,0 */
.title { color: white; }

/* specificity 0,2,0 — wins, even though it is written first */
.card .title { color: red; }

/* specificity 1,0,0 — wins over both. This is why we avoid ids. */
#hero .title { color: blue; }

Two selectors that always score 0,0,0 and are therefore easy to override — which is exactly what makes them good: :where() and the universal selector *. 

/* Both of these style the same links… */
.prose a          { color: red; }   /* 0,1,1 — hard to override later */
:where(.prose) a  { color: red; }   /* 0,0,1 — a suggestion, not a fight */
Debugging the cascade: open DevTools, select the element, look at the Styles pane. Struck-through declarations lost. Hover the selector to see its specificity. Ninety percent of "CSS is broken" is a rule losing a tiebreak you didn't know about.

03 — The box model

Every element is a box: content, wrapped in padding, wrapped in a border, with margin pushing other boxes away outside it. 

/* The one line that makes sizing sane. */
*, *::before, *::after {
  box-sizing: border-box;
}

/* width:200px now means the box is
   200px wide, full stop — padding and
   border are counted INSIDE it. */
.box {
  width: 200px;
  padding: 20px;
  border: 4px solid red;
}
border-box vs content-box
border-box → 200px wide
content-box → 236px wide

Margin collapse — the classic surprise

Two vertical margins that touch merge into one, and the larger one wins. A 40px bottom margin next to a 20px top margin gives you 40px of space, not 60px. Horizontal margins never collapse, and the collapse stops if there is a border, padding, or a flex/grid container in between.

The modern fix: stop fighting it. Use gap on a flex or grid parent, or the "owl" pattern: .stack > * + * { margin-block-start: 1rem; } — which is exactly what .stack in base.css does.

04 — Color & units

color: #e60012;                      /* hex — fine, unreadable */
color: rgb(230 0 18);                /* modern space-separated syntax */
color: rgb(230 0 18 / 0.5);          /* alpha with a slash, no rgba() needed */
color: hsl(355 100% 45%);            /* hue, saturation, lightness — easy to tweak */
color: oklch(55% 0.22 25);           /* perceptually uniform: 55% looks 55% at every hue */
color: color-mix(in srgb, red 20%, black);  /* blend without a preprocessor */

Units, and when each one is right:

UnitRelative toUse for
pxnothingBorders, tiny fixed details.
remthe root font sizeDefault choice. Spacing, font sizes — respects the user's browser setting.
emthe element's own font sizePadding inside a button that should scale with its text.
%the parentWidths inside a container.
chwidth of a "0"Reading measure: max-width: 68ch.
vw / vhthe viewportFull-bleed sections. Beware 100vh on mobile — prefer 100dvh.
frfree space in a gridGrid tracks, and nothing else.

05 — Typography

This theme runs on exactly two typefaces: a heavy display face screaming in all-caps, and a plain workhorse for body text. Two is usually the right number. 

h1 {
  font-family: "Archivo Black", Impact, sans-serif;
  /* fluid: min, scaled, max — no media query */
  font-size: clamp(2.5rem, 2rem + 2.4vw, 3.9rem);
  line-height: 1.05;          /* tight for big text */
  letter-spacing: 0.01em;
  text-transform: uppercase;
  text-wrap: balance;         /* no orphan words */
}

p {
  line-height: 1.6;           /* loose for small text */
  max-inline-size: 68ch;      /* ~68 characters per line */
  text-wrap: pretty;
}

Line height and measure do more for readability than the choice of typeface ever will.

Always ship a fallback stack. Your webfont can fail to load, and the page still has to be readable: font-family: "Archivo Black", Impact, sans-serif;

06 — Custom properties

Custom properties are real, live CSS values. They inherit, they cascade, and JavaScript can change them at runtime — none of which is true of a Sass variable. 

:root {
  --accent: #e60012;
  --space-m: 1.5rem;
}

.card {
  border-color: var(--accent);
  padding: var(--space-m);
  /* second argument = fallback if the property is not set */
  gap: var(--card-gap, 0.5rem);
}

/* Re-declare on a scope and everything inside it changes. */
.card.is-danger { --accent: #ff5555; }
This is the whole theming system. Open assets/css/theme-persona.css — it is barely more than a :root block. Swap it for theme-starwars.css in the <head> and this page becomes a spaceship without one component changing.

07 — States & pseudo-elements

Pseudo-classes (one colon) select an element in a state. Pseudo-elements (two colons) invent a child element for you to decorate with. 

.btn:hover          { filter: brightness(1.1); }
.btn:focus-visible  { outline: 2px solid var(--accent); }  /* keyboard only */
.btn:disabled       { opacity: .5; cursor: not-allowed; }
li:nth-child(odd)   { background: var(--surface); }
p:first-of-type     { font-size: 1.2em; }

/* A red rule above every card title — zero extra HTML. */
.card h3::before {
  content: "";        /* REQUIRED, or nothing renders */
  display: block;
  inline-size: 2.5rem;
  block-size: 4px;
  background: var(--accent);
}
Never write outline: none on a focusable element unless you replace it in the same rule. Keyboard users navigate by that ring. Use :focus-visible so mouse clicks stay clean and keyboard focus stays obvious.
