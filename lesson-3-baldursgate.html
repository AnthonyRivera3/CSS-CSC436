01 — Nesting

Native nesting landed in every browser, and it does what Sass nesting did: keeps a component's rules together. The & stands for the parent selector. 

.tome {
  padding: var(--space-l);
  border: 2px solid var(--accent-2);

  & h3 { font-family: var(--font-display); }

  &:hover { box-shadow: 0 0 0 3px var(--accent-2); }

  /* & is required when the nested selector starts with an element name */
  & p { color: var(--text-dim); }

  @media (min-width: 40rem) { padding: var(--space-xl); }
}
Nest two levels, then stop. Deep nesting produces long, high-specificity selectors that are miserable to override — the exact problem cascade layers were invented to solve. If you are four levels deep, the component wants splitting.

02 — :has(), the parent selector

For twenty years CSS could only look down the tree. :has() lets a rule depend on what an element contains, or on what follows it — which quietly removes a whole category of JavaScript. 

/* a card that contains an image gets a different layout */
.card:has(img) { grid-template-columns: 120px 1fr; }

/* style a form field's wrapper from the state of the input inside it */
.field:has(input:invalid) { border-color: var(--accent); }

/* "if any dialog is open, stop the page behind it scrolling" */
body:has(dialog[open]) { overflow: hidden; }

/* dim every sibling except the hovered one */
.party:has(.member:hover) .member:not(:hover) { opacity: .55; }

03 — Cascade layers

@layer lets you declare the priority order of whole groups of CSS up front. A rule in a later layer beats a rule in an earlier one no matter how specific the earlier one is. This is the real cure for !important wars. 

/* Declare the order once, at the top of your stylesheet. */
@layer reset, framework, components, theme, utilities;

@layer framework {
  #sidebar .nav a { color: blue; }   /* specificity 1,2,1 — and it still loses */
}

@layer theme {
  a { color: crimson; }              /* specificity 0,0,1 — and it wins */
}
Where this earns its keep: importing a third-party stylesheet into a low layer — @import url(bootstrap.css) layer(framework); — so your own single-class rules can override the library without a single !important.

04 — Colour & size functions

/* clamp(MIN, PREFERRED, MAX) — fluid sizing with no breakpoints */
h1    { font-size: clamp(2rem, 1.5rem + 2.5vw, 3.8rem); }
.wrap { inline-size: min(100% - 2rem, 1180px); }
.side { inline-size: max(240px, 20%); }

/* colour maths, in the browser, at runtime */
.btn:hover  { background: color-mix(in oklch, var(--accent) 85%, white); }
.tag        { background: color-mix(in srgb, var(--accent) 18%, transparent); }

/* relative colours: derive from an existing one */
.muted      { color: rgb(from var(--accent) r g b / 40%); }

06 — Transitions & keyframes

A transition animates between two states you already have. A keyframe animation runs on its own schedule. 

/* Transition: name the properties. Never write `transition: all`. */
.btn {
  transition: transform 180ms cubic-bezier(.2,.8,.2,1),
              background-color 180ms ease;
}
.btn:hover { transform: translateY(-2px); }

/* Keyframes */
@keyframes pulse {
  from { opacity: 1; }
  to   { opacity: .4; }
}
.loading { animation: pulse 1.2s ease-in-out infinite alternate; }
Only two properties are cheap to animate: transform and opacity. They run on the compositor. Animating width, top, or margin forces the browser to re-lay-out every frame — that is what a janky animation is.
Motion is an accessibility setting. Wrap decorative motion in @media (prefers-reduced-motion: no-preference), or kill it globally the way base.css does. Vestibular disorders are real and common.

07 — On the horizon

  • @scope — limit rules to a subtree without BEM-style naming gymnastics.
  • @starting-style — animate an element in, including elements entering from display: none.
  • View Transitions — cross-fade or morph between two states, and between two pages, with view-transition-name.
  • Scroll-driven animations — animation-timeline: scroll() ties a keyframe animation to scroll position, with no scroll listener.
  • Anchor positioning — tether a tooltip or popover to an element without measuring anything in JavaScript.

Check caniuse before you ship any of them, and treat them as enhancements: the page must still work when they are ignored.
